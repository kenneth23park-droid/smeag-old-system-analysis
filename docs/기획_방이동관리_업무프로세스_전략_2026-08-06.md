## 0. 한 장 요약

1. **"코딩 미착수"라는 전제가 사실이 아니다.** 작업 트리에 `deploy/api/moves.js`(279줄) · 배치도 오버레이 배선(`data.js`가 `app.roomstat_overlay` 호출, terminations로 레거시 구간 절단) · `ROOM MOVES(이동관리)` 화면과 이동 등록 모달(`index.html`)이 **이미 존재한다**(미커밋). R1의 임계경로는 "신규 개발"이 아니라 **결함 수정 + 커밋 + 결정 회신**이다.
2. **회의가 가장 명확히 예시로 든 요구 8("8/7 오전 퇴실 → 8/7 오후 입실 = 가능")이 현재 구현에서 불가하다.** 검증 V1이 날짜 단위(`eff_end >= 이동일`)로 무조건 BLOCK한다. R1 필수 수정.
3. **완료 처리에 데이터 사고 결함이 있다.** 이동 완료 시 기존 구간 종료 기록이 예외 블록 **밖**에서 커밋되어, 대상 침대 충돌 시 **학생이 옛 방·새 방 어디에도 없는 상태**가 된다. R1 필수 수정.
4. **남녀 혼숙 차단이 뚫려 있다.** 방 구역 성별값이 비면 기본 'C'(가족실)로 해석되어, BLOCK이어야 할 이성 배정이 "승인으로 통과 가능한 경고"로 강등된다. 임시방(TEMPORARY)이 같은 경로에 있다. 저비용 수정, R1 필수.
5. **요구 15건 중 완결은 2건, 사실상 미착수가 3건**(요구 3 배정최적화 · 10 호텔/캠퍼스 · 14 재배치)이다. 특히 요구 10은 라벨 문제가 아니라 **HOTEL 배정 생성 경로가 아예 없어** ⭐⭐⭐ 항목(빈방·충돌)의 판정을 오염시킨다.
6. **이 프로젝트의 성패는 알고리즘이 아니라 3개의 수동 입력 습관**(이동 가능 시간 · 청소 상태 · 이동 등록)이다. 이것 없이는 완전자동 7건이 빈 화면을 그린다. 실제로 레거시 ROOM MOVE LIST가 지금 그 상태다.
7. **검증 로직 1,232줄이 `.gitignore: *.sql`로 형상관리 밖에 있다.** 리뷰·CI·롤백 경로가 없다. 데이터 품질 게이트보다 형상관리 게이트가 먼저다.

### 4.1 요구 3·14가 "추천만"이어야 하는 이유 (결론)

1. **입력이 원천적으로 없다** — 목적함수의 핵심 축인 친구/가족 관계가 데이터로 존재하지 않는다(레거시 학생그룹 12행은 결제그룹). 관계 없이 돌린 자동 배정은 정확도가 아니라 **방향**이 틀린다.
2. **목적함수가 미합의** — 국적 축은 조직 결정으로 봉인돼 있다(C-2). 목적함수가 확정되지 않은 최적화는 자동화 대상이 아니다.
3. **제약이 soft** — "Single 유지", "원장 승인 필요"는 위반해도 되는 경우가 있다. 자동 실행기는 soft를 hard로 오해하거나 무시하거나 둘 중 하나다.
4. **비용 비대칭** — 잘못된 추천은 무시하면 끝(비용 0). 잘못된 자동 실행은 학생이 짐을 두 번 옮긴다.
5. **실증** — ROOM REPLACEMENT의 매칭 엔진이 이미 3등급 판정 + "빈자리 적은 방 먼저(파편화 최소화)" 정렬로 라이브 동작 중이다. **파편화 최소화가 곧 요구 14의 목적함수다.** 즉 "추천만"이 실효적이라는 증거가 이미 있다.

**결론**: 새 엔진을 만들지 않는다. **기존 매칭 엔진의 정렬 가산점에 ⑴ 빈 방 생성 효과 ⑵ 가족그룹 응집을 추가**하는 형태로, 관계 데이터 확보 시점에 R3에서 처리한다.

## 5. 데이터·모델 델타 전략

### 5.1 파생 vs 저장 — 4원칙

| 원칙 | 내용 |
|---|---|
| P1 | **의도는 저장, 판정은 파생.** 사람이 선언한 것(이동시각·대상침대·가능시간대·태그·예외승인)은 저장. 그것들과 시계로 재계산 가능한 것은 저장하지 않는다 |
| P2 | **`now()`가 인자로 들어가는 값은 절대 저장하지 않는다.** 잔여시간·D-day·긴급도·"오늘의 리스트" — 하루만 지나도 거짓이 된다 |
| P3 | **재현·감사가 필요한 파생은 원장이 아니라 이벤트에 스냅샷.** 승인 시점의 경고 목록, 추천 채택 시점의 점수·후보군 |
| P4 | **계약값은 파생 가능해도 저장.** 배정 시점 룸타입, 가격 스냅샷 — 마스터가 바뀌어도 당시 약속은 변하면 안 된다 |

### 5.2 항목별 결론

| 항목 | 결론 | 근거 |
|---|---|---|
| 이동 가능 시간 | **저장**(코드값 4종 + 시각) | P1. 자유텍스트 금지 — 우선순위·정렬이 동시에 죽는다 |
| 우선순위 🔴🟡🟢 | **파생 전용(저장 금지)** | P2. 입력 3개(다음 입실일·가능시간·차단 유무)가 전부 외부 변동 |
| 장기/졸업예정 | **파생**(예외 지정만 저장) | P2 |
| 관리자 메모 | **저장**(태그 + 자유 병행) | P1. 태그만이면 뉘앙스가, 자유만이면 필터가 죽는다 |
| 방 타입 라벨 | **파생** — 마스터 테이블 만들지 않음 | 정원+구역타입으로 유도 가능. 마스터를 만들면 **이중 정본**이 되어 한쪽만 바뀌면 검증이 조용히 틀린다 |
| 빈 방 상태/색 | **파생** | 4중 합성 결과의 라벨 |
| 충돌 판정 | **파생**(승인 시점만 이벤트 스냅샷) | P3. 저장되는 것은 "무엇을 눈감아 주기로 했는가"라는 의도뿐 |
| 일일 이동 리스트 | **온디맨드 뷰 — 스냅샷 테이블 없음** | 저장하면 리스트와 원장이 갈라져 현장이 다른 진실을 본다. 과거 재현은 이벤트 리플레이 |
| 재배치 추천 결과 | **저장하지 않음.** 채택된 이동에만 근거(엔진버전·가중치·점수·대안·입력해시) append | 저장된 제안은 곧 오답이 되고, 오답을 클릭한 책임 소재가 생긴다 |

## 7. 화면·색상 통합안

### 7.1 색 충돌의 정체와 해소 원칙

세 출처가 서로 다른 **축**을 칠하고 있어 한 셀에 색 하나로는 반드시 충돌한다.
- 축 A = 재실 사실(입실/퇴실/예약/재실) ← 현행 코드
- 축 B = 침대 가용성(빈방/사용가능/청소/잠금) ← 회의 §2
- 축 C = 신전산 사건(이동예정/충돌/승인대기) ← 회의 §11

**결론(2레이어 분리)**: **배경 채움 = 축 A·B / 테두리·세로바·코너마커·배지 = 축 C.**
축 C를 배경색으로 칠하지 않으므로 레거시 색 파리티를 지키면서 이동·충돌을 동시에 표현할 수 있다.

### 7.2 확정 팔레트

**레이어 1(배경 8종)** — 빈방(흰) · 사용가능(초록 연한+좌측바 `AVL`) · 입실예정(노랑 `RSV`) · 입실(빨강 `IN`) · 재실(무채 X무늬 `OCC`) · 퇴실예정(주황 `OUT`) · 청소(회색 사선해칭 `CLN`) · 사용불가(보라 `LOCK`)
**레이어 2(오버레이 5종, 배경을 덮지 않음)** — 이동예정 나감(파랑 우측바 `→`) · 이동예정 들어옴(파랑 좌측바 `←`) · 충돌(빨강 2px 외곽선+사선해칭 `⚠`) · 정보확인필요(노랑 점선 `?`) · 승인대기(회색 코너점 `⏸`)

### 7.3 충돌 해소 결론표

| 충돌 | **결론** | 근거 |
|---|---|---|
| 초록: 회의 "사용가능" vs 현행 "예약" | **회의 채택** — 초록=사용가능, 예약은 노랑으로 | 회의 §2·§11이 일치하는 유일한 항목. 여기서 파리티를 양보하는 비용이 가장 싸다 |
| 노랑: "예약" vs "입실예정" vs "정보확인필요" | 앞의 둘은 **같은 것의 다른 이름** → 노랑=입실예정으로 통합. 정보확인필요는 **노랑 점선 테두리**로 강등 | 배경을 뺏지 않는다 |
| 빨강: "입실" vs "충돌" | **둘 다 산다** — 입실=솔리드 채움, 충돌=해칭+외곽선+⚠ | 충돌은 희소 이벤트라 외곽선이 오히려 눈에 띈다 |
| 파랑: 회의 "이동예정" vs 기획서 "재실 중" | **기획서 폐기** — 파랑=이동예정 전용 | 재실은 이미 무채 X무늬로 관행이 굳었고, 파랑을 재실에 쓰면 요구 1·11이 표현 수단을 잃는다 |
| 회색/흰 | 흰=완전 빈방, 회색 사선해칭=청소 | 해칭이 있어 흑백 인쇄에서도 구분 |
| 보라: 현행 "퇴실" vs 기획서 "잠금" | **잠금 전용** — 퇴실은 주황으로 이관 | 방막기가 이미 별도 렌더라 의미가 일관됨 |
| **전환 시점** | **병행기간 중에는 레거시 팔레트 기본 + 신 팔레트 토글 제공. 전면 전환은 병행 종료 후** | 병행기간 내내 구·신 배치도를 **사람이 눈으로 대사**한다(§8.4 C5). 색이 반대가 되면 그 대사가 매일 오독을 낳는다 |

**색맹·인쇄 대응(필수)**: 색 단독 사용 금지(전 토큰이 아이콘+텍스트 동반) · 형태 4언어(채움/해칭/세로바/외곽선) · 적록 인접 시 명도 대비 확대 · 범례 상시 노출 · **일일 이동 리스트는 색 없이 완결**(현장 인쇄).

| C4 | 레거시 예약(입·퇴실) 입력은 당분간 구전산 유지 — 범위를 넓히면 롤백 불가 |

**구전산 오입력 발견 시**: 자동 반영·자동 삭제 금지 → 대장 기록 → 기숙사가 동등한 이동을 사후 등록(사유='레거시 입력 정합') → 입력자 재공지, 3회 반복 시 권한 회수.

**롤백 조건(사전 합의)**: 실제 이중 배정 발생 → 즉시 전면 롤백 / 완료 실패 3건+/일 → 부분 롤백 / 표시 불일치 5건+/일 → 표시 신뢰 중단 / **원본 레거시 변경 흔적 발견 → 전면 중단 + 감사**.
**롤백 비용은 낮다** — 신전산 쓰기는 전부 오버레이고 원본은 불변이다. 되돌리기 = 이동 전건 취소 + 오버레이 무시. **이 점을 교육에서 명시해 전환 공포를 낮춘다.**

### 9.2 R1 — "이동을 시스템에 남기고, 배치도에서 눈으로 확인한다"

> **체감 가치**: 오늘 옮길 학생이 종이·기억이 아니라 화면 한 장에 있고, 옮기면 안 되는 방은 저장 자체가 막힌다.

| 구분 | 항목 |
|---|---|
| **결함 수정(최우선)** | F1 완료 원자성 · F2 구역 성별 결측/임시방 · F3 같은 날 교대 · F4 12:00 가정+음수 간격 · F5 멱등키 잔존 |
| **기능** | 이동 등록·확정·완료·취소·**연기** · 검증 3분류 · 일일 이동 리스트(+인쇄) · 배치도 오버레이 색·배지 · 우선순위 3등급(일 단위) · 체류정보 결측 입력 UI |
| **소급 불가 필드** | 이동 가능 시간 2종 · 동반 이동 배치키 · 취소 사유 코드 · 열쇠/짐 확인 · 학생 통보 · 외부 숙소 비트 · 연기 횟수 |

| **운영** | 외부 숙소 이동 시 원 침대 자동 보류 · S2 모바일 반응형 + 1탭 완료 · 다건 선택 등록 최소 UI |
| **전제** | 형상관리 편입(SQL 4파일) + 라이브 적용 확인 · D1·D2·D4·D6 회신 · 신전산 단독 운영 공지 |
| **회귀 대상** | 배치도 렌더 · 엑셀 export · 방막기 표시 · parts 조합 조회 · 응답 스키마 리비전 승격 |

### 9.3 R2 — "청소·가족실·방타입까지 시스템이 대신 검사한다"

청소 원장 + 입력 화면 · 가족그룹(관계 데이터) → 가족실 경고→차단 승격 · 운영정원/단독사용 잠금 · 방 타입 라벨 표시 · 관리자 태그 사전 + 장기/졸업 배지 · 이동 가능 시간 자동 연쇄 · 동반 이동 UI · 실행순서 컬럼 개명 · 월간 감사 보고.
**전제**: R1 운영 2주 + D5 회신 + **청소 담당 업무 합의**(누가 언제 완료를 누르나).

### 9.4 R3 — "빈 방을 만들 재배치를 시스템이 제안한다"

캠퍼스 매핑 라벨 · 배정 최적화·재배치 추천(**제안만**) · 충돌 자동탐지 대시보드 · 데이터 정리 목록(구전산 오입력 감지).
**전제**: 매핑표 수령 · **관계 데이터가 실제로 채워져 있을 것**(빈 테이블이면 추천 품질 미달 → 착수 연기).

### 9.5 R1에서 뺀 것과 그 근거

| 뺀 것 | 왜 빼도 업무가 돌아가는가 |
|---|---|
| 청소 원장·담당자 화면 | 청소 여부는 지금도 현장 확인으로 처리한다. R1은 시간 간격만으로 위험 이동을 거른다(추가 입력 0). 원장을 만드는 순간 **매일 눌러줄 사람**이 필요해져 부담이 R1 정착보다 커진다 |
| 가족그룹 | 관계 데이터가 **어디에도 없어** R1에 넣으면 빈 테이블에 대고 차단을 거는 꼴 — 정상 배정까지 막힌다 |
| 방 타입 라벨 마스터 | 이미 정수 비교 경고가 동작한다. 라벨은 **표현**의 문제이지 판정의 문제가 아니다 |
| 운영정원 잠금 | "3인실을 1인실로 판매"는 지금 방막기로 운영 중이고 그 경로는 살아 있다 |
| 재배치·최적화 추천 | 추천이 없으면 지금처럼 사람이 판단한다(=현행 유지). 잘못된 추천은 현행보다 나쁘다 — 오배정 책임이 시스템으로 넘어온다 |
| 이동 가능 시간 **자동 연쇄** | 입력·표시·정렬만으로도 담당자가 순서를 정할 수 있다. 시각 없는 자동 연쇄는 **틀린 자동화**가 된다 |
| 우선순위 시(時) 단위 해상도 | 레거시에 시각이 없다. 일 단위만으로도 "오늘 반드시"라는 회의의 원래 목적은 달성된다 |
