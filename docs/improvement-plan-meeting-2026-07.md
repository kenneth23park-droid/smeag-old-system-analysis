## 0. 요약 — 무엇을 먼저 할 것인가

요청 11건을 **효과 × 공수 × 의존성**으로 4구간으로 나눴습니다.

| 우선 | 항목 | 이유 |
|---|---|---|
| **P0 (기반)** | ⑨ 데이터 조회/머지 오류 · ③ 룸-리스트 실시간 연동 | 다른 기능 정확도의 뿌리. 데이터 재이관 + 예약 단일소스가 선행돼야 나머지가 신뢰 가능 |
| **P1 (고효과·저공수)** | ⑥ 픽업 자동정렬 · ⑤ 입·퇴실 리스트 추출 · ⑧ 비행시간 입력 간소화 · ⑪ 기능 반영 양식 | 즉시 실수↓·업무↓. 데이터 의존 적음 |
| **P1 (중공수)** | ① 드래그 기간 방막기 · ④ 가족 인보이스 자동조정 | 반복업무 큰 폭 절감. 기존 엔진(예약/커미션) 위에 얹음 |
| **P2 (심화)** | ② 방 쪼개기 · ⑦ 통합 드라이버 리포트 · ⑩ 전반 간소화 | 앞 단계 완성 후 자연스럽게 확장 |

> 공통 임계경로: **① 구전산 데이터 재이관(90,524행 + 등록일·생년월일·객실)** 과 **Supabase 쓰기 배선(anon 키)** — 이 두 개가 풀려야 P0가 실질 완성됩니다.

## 1. 기숙사 관리 및 예약

### ① 드래그하여 방 막기(기간 Block)
- **요청**: 아이디 만들고 기간 잘라 넣는 대신, 화면에서 **기간을 드래그해 한 번에 방 막기** 버튼.
- **현재**: 배치도(DORM STATUS)에 드래그 방막기 있음 — 단, **방 전체를 막는 방식**(기간 개념 없음).
- **개선안**: 간트에서 **가로(날짜축)로 드래그 → 그 기간만 Block** 생성. 내부적으로 `app.reserve_insert`에 예약유형 `Block`(가상 점유)으로 저장 → 정원/충돌 프리플라이트 그대로 재사용. Block도 이력·해제 가능.
- **범위**: 배치도 드래그 UX + Block 유형 저장/표시/해제.
- **의존성**: 예약 쓰기계층(write_layer.sql, 이미 있음) 라이브 연결.
- **미결정**: Block 사유(공사/청소/보류) 분류 필요 여부, 부분날짜(당일 반나절) 허용 여부.

### ② 방 쪼개기(Splitting)
- **요청**: 3주 학생을 1주 A방 + 2주 B방으로 나눠 배정하는 과정을 직관적으로.
- **현재**: ROOM MOVE PATH(이동 이력)는 표시됨. 이동(`reserve_move`)은 있으나 **한 번에 분할 배정하는 UI 없음**.
- **개선안**: ROOM REPLACEMENT에 **"기간 분할" 모드** — 전체기간을 구간으로 쪼개 각 구간에 방 지정 → 연속 예약 N건을 원자적으로 생성(사이 공백/중복 자동검증). 결과는 이동경로칩으로 시각화.
- **범위**: 분할 입력 UI + 다건 예약 원자 생성 + 검증.
- **의존성**: ① 예약계층, ③ 실시간 연동.
- **미결정**: 분할 시 요금/인보이스 자동 재계산까지 포함할지.

### ③ 룸 앤 리스트 ↔ 실제 점유 실시간 연동
- **요청**: '룸 앤 리스트'와 실제 기숙사 점유가 **실시간·정확** 연동.
- **현재**: 임베드 데이터에 **객실 값 0%** → 배치도 이름매칭으로 81%만 도출(추정). 리스트·배치도가 별도 출처라 어긋남.
- **개선안(기반)**: `public.dorm_reservations`(예약)를 **단일 진실원본(SSOT)** 으로 삼아 배치도·리스트·현황을 모두 여기서 파생. 저장은 write_layer RPC 경유(멱등·충돌검증).
- **범위**: 데이터 재이관(객실 포함) + 모든 화면을 SSOT 기준으로 재배선.
- **의존성**: **데이터 재이관(P0)**, anon 키.
- **미결정**: 재이관 범위 — (A) 현재 12,150 + 누락 3필드 / (B) 전체 90,524 + 전필드. → **결정 요청**.

## 2. 학생 관리 및 정산

### ④ 가족 단위 인보이스 자동 조정
- **요청**: 공부하는 구성원 + 비공부 보호자 혼합 가족에서, **커미션·총합을 시스템이 쉽게 맞추기**. 지금은 수기로 차액 계산해 특정 인원에 추가금.
- **현재**: 커미션 엔진(`calcComm`: 나라%+코스액+빌딩액) + 인보이스 멱등 발행 있음. **가족 묶음·총합 목표 배분은 없음**.
- **개선안**: (a) **가족 그룹** 지정(구성원 묶기, 학습/비학습 표시), (b) **목표 총합 입력 → 차액 자동 배분**(특정 인원에 조정액 자동 반영, 근거 표시), (c) 가족 합산 인보이스/개별 인보이스 선택 발행.
- **범위**: 가족 그룹 모델 + 총합 조정 계산기 + 인보이스 라인 조정.
- **의존성**: 커미션 규칙 실요율 확정(현재 샘플값).
- **미결정**: 조정액을 "커미션 항목"으로 볼지 "별도 조정 라인"으로 볼지(회계 표기).

### ⑤ 입·퇴실 리스트 구분 추출
- **요청**: 월=졸업(Out), 목/금=신입(In)을 **기간 설정으로 명확히 구분해 엑셀** 추출.
- **현재**: STUDENT LIST/Financial 필터는 있으나 **입·퇴실 전용 구분 추출 없음**.
- **개선안**: **IN/OUT REPORT** 화면 — 기간 지정 + 요일규칙(월=Out, 목·금=In, 사용자 조정 가능) → In/Out 분리 표 + **엑셀 다운로드**.
- **범위**: 전용 화면 + 요일필터 + 엑셀 export.
- **의존성**: 시작일/종료일 데이터 신뢰도(재이관과 연결).
- **미결정**: 공휴일·비정규 입퇴실 예외 처리 규칙.

## 3. 픽업 및 교통 관리 자동화

### ⑥ 픽업 리스트 자동 정렬
- **요청**: **편명·도착 날짜·시간** 기준 자동 정렬. 지금은 수기 확인 → 날짜 착각 실수.
- **현재**: 픽업 컬럼 존재. **자동정렬 없음**.
- **개선안**: 도착 **일시 파싱 → 날짜→시간→편명 다중정렬**, 날짜별 그룹 헤더, 시간 이상치(과거/공란) 경고 하이라이트.
- **범위**: 정렬 로직 + 픽업 화면 정렬/그룹 UI.
- **의존성**: ⑧ 입력 정규화(정렬 정확도의 전제).
- **미결정**: 정렬 기준 우선순위(날짜→시간→편명 확정?), 시간대(현지/출발지).

### ⑦ 통합 드라이버 리포트
- **요청**: 졸업생+신입생 정보로 **드라이버 배정용 단일 통합 리포트** 자동 생성.
- **현재**: 없음.
- **개선안**: ⑤(In/Out) + ⑥(픽업정렬) 결과를 합쳐 **드라이버 배정 리포트 1파일**(시간순·차량/기사 칸 포함) 생성 → 인쇄/엑셀.
- **범위**: 리포트 조립 + 배정 칸 + export.
- **의존성**: ⑤·⑥ 선행.
- **미결정**: 차량/기사 마스터를 시스템에서 관리할지(수기 칸만 둘지).

### ⑧ 비행 정보 입력 간소화
- **요청**: 도착시간(AM/PM 등) **복붙 원활** 또는 더 간편한 입력 UI.
- **현재**: 일반 입력.
- **개선안**: **스마트 시간 입력**(다양한 형식 붙여넣기 자동 파싱: "7:30 PM", "19:30", "오후 7시반" 등 → 표준화), AM/PM 토글, 편명 자동대문자, 붙여넣기 시 여러 줄 일괄 입력.
- **범위**: 입력 컴포넌트 + 파서.
- **의존성**: 없음(독립·저공수).
- **미결정**: 허용 입력 형식 목록 확정.

## 4. 행정·운영 효율화 (공통)

### ⑨ 데이터 조회/머지 오류 수정 — **P0**
- **요청**: 조회·머지 오류 조속 해결.
- **원인(기확인)**: (a) 기본 픽업주 날짜필터 → 해결(전체표시), (b) **데이터 격차** — 생년월일 컬럼 없음, 등록일 1%·객실 0%, 12,150은 전체 90,524의 부분집합.
- **개선안(기반)**: **구전산 재이관** — `student_info.sql`(90,524)에서 등록일(s_regdate)·생년월일(s_jumin)·객실(s_room) 포함 재추출 → 조회/머지 기준 통일(SSOT).
- **의존성**: 재이관 범위 결정(③ 미결정과 동일).
- **미결정**: (A) 12,150+3필드 / (B) 전체 90,524+전필드.

### ⑩ 전반 간소화·직관화 (온보딩)
- **요청**: 초보 매니저도 쉽게 배우도록 프로세스 간소화.
- **성격**: 상시 원칙(단일 기능 아님).
- **개선안**: 기본언어 영어(기적용), 핵심 동선 최소 클릭화, 위험작업 확인창(멱등·프리플라이트 이미 있음)을 쉬운 문구로, 화면별 도움말/툴팁, 표준 필터바 일관화.
- **적용**: 각 기능 구현 시 체크리스트로 반영.

### ⑪ 팀별 기능 반영 양식 — **본 문서 §6 초안 제공**
- **요청**: 팀별 요구를 체계적으로 반영할 공통 **기능 반영 양식**.
- **제공**: 아래 §6 표준 양식(요청→전산 기입 이중 구성). 도입 시 이 양식으로 백로그 관리.
