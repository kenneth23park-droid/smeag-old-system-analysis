## B. 기능별 상세 테스트

### B1. 수강등록 (REQ-101/102)
- [ ] 검색기준 `특정일 재학` 으로 2026-07-15 조회 → 시작일≤7/15≤종료일 학생만 나온다(D 대조).
- [ ] 코스 5개(Pre-TOEFL·TOEFL 3.5/4.0/4.5/5.0) 동시 선택 → 1회 조회로 합집합 표시.
- [ ] 페이지당 15/30/50/100 전환이 유지된다.
- [ ] 미처리 패널: 객실 배정 삭제 → 해당 학생 즉시 등장, 재배정 → 사라짐.
- [ ] 미처리 100건 이상일 때 상단 필터·표가 가려지지 않는다.
- [ ] 담당자·캠퍼스·등록일 범위 필터 각각 동작.

### B2. 기숙사 현황 (REQ-103/104)
- [ ] 7월 선택 → 초기 가로 스크롤 위치가 7/1.
- [ ] 이동한 학생: 이동 전 방과 이동 후 방 **양쪽** 행이 강조·표시된다.
- [ ] 같은 방·같은 날 퇴실+입실 → 대각선 2이벤트 표시 + 툴팁에 둘 다.
- [ ] 방구분 드롭다운 CAPITAL 24 / ENCANTO 6(레거시 순서 동일).
- [ ] 전체 조회 335방·713베드 렌더 < 1s, 콘솔에러 0.
- [ ] 침대 `r_idx` 가 응답에 포함되어 이동 대상 침대를 특정할 수 있다.

### B3. 통계 (REQ-105/106/206)
- [ ] MC Report 2: 시작일 선택 → 그 날부터 15일 컬럼, 코스별 행, 날짜별 합계.
- [ ] 새 코스 생성 → 새로고침 없이(또는 재조회 후) MC2 에 행 추가.
- [ ] 비활성 코스는 설정에 따라 숨김.
- [ ] 헤더(코스·날짜) 고정 + 가로·세로 스크롤 + 엑셀 = 화면 값과 동일.
- [ ] 임의 5일에 대해 **배치도 / 일별 입퇴실 / STDNT STATUS 재학생 수 3화면 동일**.
- [ ] 식수 예상 인원은 재학생 수와 다른 값으로 별도 표시된다(같은 날 퇴실+입실 동시 계상).
- [ ] 관리용 가상 학생(준블락·staff 등)이 재학생 수에 포함되지 않는다.

### B4. 마스터 관리 (REQ-107/108/§13)
- [ ] 캠퍼스 신규 생성 → 수강등록·코스·기숙사·객실·MC2·STDNT STATUS·Admission·통계·권한 9곳에 자동 노출.
- [ ] 캠퍼스 표시명 변경 → 기존 학생·객실·인보이스·통계 수치 불변(ID 참조 확인, D).
- [ ] 카테고리 정렬 변경 → 배치도·DORM LIST·DORM SEARCH 순서 동시 반영.
- [ ] 학생 이력이 있는 객실: 최대인원 축소·타입 변경·캠퍼스 변경·삭제 **차단**되고 사유 안내.
- [ ] 객실 비활성 → 신규 배정 목록에서 사라지고, 기존 기록·인보이스는 유지.
- [ ] 동일 캠퍼스·카테고리 내 방번호 중복 생성 차단(기존 중복은 리포트로만).

### B5. 인보이스·가격 (REQ-110/111)
- [ ] 발행 버튼 연타·완료 후 재클릭 → 1건만 생성, 중복 안내(번호·시각·발행자).
- [ ] 발행 후 코스 가격 변경 → 기존 인보이스 금액·상세 불변(D).
- [ ] 가격 일괄수정: 미리보기에 대상 건수·전후 비교 → 적용 → 변경 로그·엑셀.
- [ ] 일괄수정 중 1건 실패 → **전체 롤백**(부분 반영 0건, D).
- [ ] 통화·NET 정의가 화면·문서·DB 에서 동일(정책 확정 후).

### B6. 감사 로그 (REQ-109)
- [ ] 학생명·ID·객실번호·작업자·기간·유형·캠퍼스 각 검색 동작.
- [ ] 2019년 이력 조회 가능(과거 데이터 접근).
- [ ] 신전산에서 한 방막기·배정 변경이 작업자와 함께 같은 화면에 나온다.
- [ ] 일반 사용자(Lv8 미만) 접근 403, 삭제·수정 수단 없음.

### B7. 전기·수도 (REQ-205)
- [ ] 단가 변경(학생/직원/수도) → 적용일 이후 계산만 바뀌고 과거분 불변.
- [ ] 실거주일 기준 분담: 기간 일부만 거주한 학생에게 일할 계산(D 수기 대조 3건).
- [ ] 직원 단가가 이름 접두가 아니라 `person_kind` 로 적용된다.
- [ ] 방 전체·학생 개인 조회 + 계산식 표시 + 엑셀 + 수정이력.
- [ ] 레거시 화면 수치와 동일 기간·동일 방 3건 대조 일치.

### B8. 권한 (REQ-212)
- [ ] 역할 생성·권한 편집이 **DB 에 저장**되고 다른 브라우저에서도 동일하게 적용.
- [ ] 캠퍼스 담당자 계정: 자기 캠퍼스 데이터만 조회, 타 캠퍼스 403.
- [ ] 비로그인 401 / Lv1 내부조각 403 / 유학원 확정계정은 자기 유학원만 / Lv9 정상 — 인가 매트릭스 재실행.
- [ ] 삭제 계열 작업은 비밀번호 재확인 없이는 403(토큰 위조·만료·타계정 전부 거부).

### B9. 성능·UI (REQ-211/§26)
- [ ] 학생 2,000+ · 객실 수백 · 기간 1개월+ · 미처리 100건+ 에서 화면이 무너지지 않는다.
- [ ] 상단 헤더·좌측 객실열·날짜 헤더 고정 유지(스크롤 0/700/1600/4000).
- [ ] 1024·1280·1366·1600 폭에서 가로 넘침 없음, ACTION 열 잘림 없음.
- [ ] 전 화면 순회에서 `undefined`/`NaN`/`[object Object]` 0건, 콘솔에러 0.

## E. 라이브 검증 주의 (사고 재발 방지)

1. 라이브(smeag-bay) 는 Edge 세션 게이트가 걸려 있어 **로그인 계정이 있어야** 클릭 검증이 된다.
2. 라이브에서 쓰기 검증을 할 때는 **대상 행의 원본값을 먼저 확보**하고 **종료 시 반드시 복원**한다(2026-07-30 실데이터 3건 변경·복원 사례).
3. 가능하면 **전용 테스트 학생·테스트 객실**을 쓴다(도입 예정).
4. 배포 후에는 `vercel alias set smeag-bay.vercel.app` 재지정을 확인한다(별칭이 구배포에 고정되는 사례 반복됨).
