# 기획서: index.php로 레거시 도메인에 신시스템 직결 (컷오버 브릿지)

> 아이디어(사용자): 레거시 그누보드4는 진입이 `adm/index.php`. 기존 **도메인·페이지·이미지**를 그대로 활용해,
> **겉모습=레거시 그대로 / 뒷단=신시스템(프로그램+데이터 모두 Supabase)** 로 바로 연결.
> 본 문서는 **기획만**(코딩 X). 작성 2026-07-26.

---

## 1. 핵심 개념

```
[사용자] → smeadmin.com/gnuboard4/adm/index.php   ← 기존 URL 그대로
                     │  (index.php = 얇은 브릿지)
                     ▼
        신시스템 SPA(현 prototype.html) 서빙
                     │  로직·데이터
                     ▼
              Supabase (신 DB/RPC)         ← 구 MySQL 미사용
```

- **겉(프론트)**: 레거시 로그인·이미지·URL 유지 → 사용자·북마크·유학원 링크 그대로.
- **속(백엔드)**: 화면 렌더·CRUD·인증 전부 **신시스템 + Supabase**. 구 PHP/MySQL 로직은 우회.
- **효과**: 별도 신규 도메인 홍보 없이, 기존 사이트에 접속하면 곧바로 신시스템이 뜬다 → 컷오버가 매끄럽다.

> 보너스: **레거시 서버 위**라서 기존 이미지 자산(`skin/.../img/*.gif`, 로고·지구본·하늘배경)이 **실제로 존재** → 앞서 정한 "CSS 근접 재현" 대신 **진짜 레거시 이미지**를 그대로 쓸 수 있음(픽셀 100% 일치). 오프라인 프로토타입 제약이 사라짐.

## 2. 구현 방식 3안

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A. 내장(embed)** | index.php가 신 SPA의 HTML을 **직접 출력**(빌드 결과를 레거시 서버에 배치) | 단순·자기완결, 레거시 이미지 직접 사용 | 배포마다 서버에 파일 갱신 필요 |
| **B. 프록시(proxy)** | index.php가 Vercel(smeag-bay) 내용을 **서버측 fetch→출력** | 신 배포가 Vercel 한 곳, 자동 반영 | PHP 프록시·헤더 처리, 지연·장애전파 |
| **C. 리다이렉트/iframe** | index.php가 Vercel로 리다이렉트 또는 iframe 삽입 | 가장 쉬움 | URL이 바뀌거나(iframe) SEO·쿠키·CSP 이슈 |

**추천: A(내장) + 부분 B**. index.php는 (ⓐ레거시 세션/이미지 활용) + (ⓑ신 SPA 셸 출력) + (ⓒSupabase 연동 키 주입). 배포는 신 빌드 산출물을 레거시 서버로 올리는 스텝 1개 추가.

## 3. index.php가 하는 일 (설계)

1. **(선택) 레거시 세션 확인** — 그누보드 로그인(`bbs/login.php`) 세션이 있으면 사용자ID를 신 SPA에 전달(SSO). 없으면 신 로그인(레거시 스킨)으로.
2. **신 SPA 셸 출력** — 현 `prototype.html` 본문 + `window.SUPA_URL`/`window.SUPA_ANON` 주입.
3. **레거시 자산 경로 사용** — 로고/지구본/하늘배경/주황버튼을 서버 실제 이미지로 참조(겉모습 100%).
4. **딥링크 라우팅** — 아래 §4.

## 4. 기존 페이지(URL) 활용 — 매핑

기존 북마크·유학원 링크를 살리려면 레거시 .php URL → 신 SPA 화면으로 연결:

| 레거시 URL | 신시스템 화면 |
|---|---|
| `adm/index.php` | 대시보드/메인 |
| `adm/student_list.php` | 수강등록관리 |
| `adm/room_stat3.php` | 기숙사현황(배치도) |
| `adm/uhak_agency_commission.php` | COMMISSION |
| … (66개 메뉴) | MENU 의 `u:`(레거시 파일) ↔ 렌더러 키가 **이미 매핑돼 있음** |

- 구현 옵션: (1) 각 `*.php`를 index.php로 **rewrite**(.htaccess) 후 쿼리로 화면 지정, 또는 (2) 핵심 몇 개만 개별 shim.
- **강점**: 신시스템 MENU가 이미 레거시 파일명(`u:`)을 들고 있어 **URL→화면 매핑 테이블이 사실상 완성**돼 있음.

## 6. 데이터/백엔드
- 화면·CRUD·인보이스·예약은 전부 **Supabase**(write_layer RPC·멱등·프리플라이트 기존 구축분 활용).
- 구 MySQL은 **읽지도 쓰지도 않음**(정방향 최종 이관으로 데이터는 이미 Supabase). 필요 시 역방향 일일 동기화(별건)로 구전산 백업 유지.
- **anon 키** 필요(현재 대기 중 — 임계경로).

## 7. 리스크 · 주의

1. **원본 index.php 덮어쓰기** — 레거시 `adm/index.php`를 교체하면 기존 진입이 바뀜. **반드시 원본 백업**(`index.legacy.bak.php`) + 즉시 롤백 경로 확보. (기존 "원본 불가침"은 데이터 원칙이나, 웹 진입 파일 변경도 되돌릴 수 있게.)
2. **병행운영 충돌** — 컷오버 전까지 레거시가 살아있으면, index.php만 신시스템이고 나머지 .php는 레거시 → 혼재. 컷오버 시점 명확히.
3. **CORS/CSP** — 레거시 도메인에서 Supabase 호출 허용(도메인 등록), 인라인 스크립트 정책.
4. **PII** — 레거시 서버에 신 SPA(임베드 데이터 없이 Supabase에서 로드) 배치. 임베드 방식(prototype에 데이터 주입)은 금지, **런타임 Supabase 조회**로.
5. **서버 접근권** — 레거시 서버 FTP/SSH, PHP 버전 확인 필요.
6. **캐시** — 그누보드 기존 캐시/스킨 경로 간섭.
