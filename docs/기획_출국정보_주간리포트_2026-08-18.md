# 출국(Departure) 정보 입력 · Weekly Report 자동화 기획서

작성일 2026-08-18 · 상태: **기획(코딩 착수 전)**
원본 산출물: `2026.08.03 Weekly Report.xlsx` (시트 `07.10`, 2026-08-03~08-07 주차) 실측 기준
요청 요약: ① 학생 **출발 날짜·시간** 입력(6번 창구) ② 입력 즉시 **방 추가요금 / 해당 방 연장가능 여부** 자동 판정 ③ **센딩 요청 시 센딩비 반영** ④ **미성년(한국 만18 미만 / 외국 만17 미만) 빨간 형광 배경** ⑤ **졸업식** 입력 ⑥ 무료 체류 규칙(금 시작→금 / 토 시작→금 / 일 시작→토, **당일 13:00 체크아웃 기준**)

## 0. 결론 먼저 (설계 5원칙)

1. **엑셀을 대체하는 게 아니라 "엑셀의 입력원"을 시스템으로 옮긴다.**
   현재 Weekly Report 는 **사람이 손으로 채운 결과물**이다. 우리가 만들 것은 리포트 뷰어가 아니라
   **6번 창구 접수 화면 1개(입력) + 규칙엔진(판정) + 리포트 생성기(출력)** 3단이다.
   출력은 **화면 + 기존 xlsx 레이아웃 그대로의 내보내기** 두 형태를 모두 낸다(현업이 아직 엑셀로 돌린다).

2. **"출발"은 지금 어디에도 정형 데이터로 없다.**
   레거시 `student_info.s_departure` 는 **날짜(varchar 15)뿐이고 시각이 없다**. 실제 시각은
   엑셀 `DEP. TIME` 칸에 `8:00am (7d)`, `08:30am(08d)`, `13:00PM (8D)` 처럼 **사람이 자유텍스트로** 적는다.
   → **`app.departures` 신규 원장**을 만들고 **시각을 정형 필드(time)** 로 받는다. 자유텍스트는 메모로만 남긴다.

3. **요금·연장 판정은 저장하지 않고 파생한다.** (방이동 기획서에서 확정한 원칙 그대로)
   저장하는 것은 **사람의 의도(출발일시·센딩요청·졸업식참석·예외승인)** 뿐이다.
   추가요금 금액·연장가능 여부·미성년 여부는 **조회 시점에 규칙엔진이 계산**한다. 규칙이 바뀌면 과거 화면도 같이 맞아야 하므로,
   단 **인보이스로 확정 청구된 금액만** `app.departure_charges` 에 스냅샷으로 굳힌다.

4. **원본 불가침.** 레거시 MySQL / `legacy.*` 는 읽기 전용. 쓰기는 전부 `app.*`.
   구전산 반영이 필요하면 기존 `app.change_log` → 역방향 동기화 경로를 탄다.

5. **중복 방지 필수.** 창구 입력은 더블서밋이 잦다(줄 서 있는 학생을 빠르게 처리).
   저장·센딩비 청구 전부 **더블서밋 가드 + 멱등키(idem) + UNIQUE 부분인덱스** 3중으로 막는다.

## 1. 현재 실측 (무엇이 있고 무엇이 없나)

### 1.1 Weekly Report 엑셀 구조 (`2026.08.03 Weekly Report.xlsx` / 시트 `07.10`)

| 블록 | 위치 | 열 구성 | 비고 |
|---|---|---|---|
| 제목 | B2:B4 | `Weekly Report` / `03/Aug - 07/Aug/2026` / `UPDATED 03 (Mon) Aug2026` | 주차 = **월~금** 표기 |
| **① Students' status** | B6:H10 | 주차번호 · **기준일** · New · Extension · Graduation | 기준일이 **08-08, 08-15, 08-22, 08-29 = 전부 토요일**. 즉 **입실 기준 주차(토요일)** 로 집계 |
| **② The List of graduate students** | B12:I88 | NO. · **Date** · Nat · Name · **Room No.** · **DEP. TIME** · **sending** · **age** | 76행. Date 는 전부 `2026-08-07(금)` = **졸업일=금요일** |
| **③ room change** | K11:M43 | 이름 · 현재 방 · 이동 방 | 31행. 방이동 기능과 **완전 중복** → 신전산에선 자동 채움 |
| **④ extend** | B89:I95 | NO. · Starting date · Nat · name · room · **After(이동 후 방)** · **COURSE** · age | 연장자 5행 |
| 보조 시트 | `Sheet1` B6:D16 | 이름 · 방 · 시각(`09:30am(27d)`) | 다음 주 초안 메모(임시 작업장) |

**색상 규약(실측)**
- `FFFFFF00`(노랑) 40셀 — **age 칸**에만. 값 15,15,15,16… → **현재는 만18 미만 전원 노랑**, 국적 구분 없음.
- `FF92D050`(초록) 34셀 — **행 전체**. `sending 09:00am`, `sending 15:00pm` 이 적힌 행 → **센딩 요청 행 표시**.
- `FFBED7EE` 헤더, `FFEDEDED` 줄무늬.

> ⚠️ **요청과의 차이**: 현재 노랑은 "18세 미만 일괄"이다. 신규 기준은 **한국 만18 미만 / 외국 만17 미만**이고 색은 **빨강 형광**이다.
> 즉 규칙과 색이 **둘 다** 바뀐다. (§4.4)

**실측된 데이터 품질 문제** — 그대로 두면 자동화가 안 되는 것들
- `DEP. TIME` 표기 흔들림: `8:00am (7d)` / `08:30am(08d)` / `13:00PM (8D)` / `12:00nn (8d)` / `no need`. **정오를 `nn`(noon)** 으로 쓰는 관례가 있고 `13:00pm` 처럼 오전/오후 표기가 모순이다.
- 괄호 안 `(7d)/(8d)` = **출발 일자**(8월 7일/8일). 즉 **졸업일(금)과 출발일(토)이 다른 케이스가 다수**다 → 이게 곧 §4의 추가요금 판정 대상.
- `Room No.` 에 방번호(412) · **외부숙소명**(`S hotel`, `Canberry`, `Amethyst`) · `outsider` 가 섞인다.
- `(family)` 접미사로 가족 동반을 표시 → **가족은 대표 1명만 시각이 있고 나머지는 빈칸**(예: 421호 XU JIANGFENG/XU YIYANG). **가족 그룹 개념이 데이터에 없다.**
- 번호(NO.) 가 48이 79행에, 72가 81행에 끼어드는 등 **수기 삽입 흔적**.

### 1.2 레거시 필드 (읽기 전용)

| 대상 | 현황 | 이번 기획에서의 한계 |
|---|---|---|
| `student_info.s_departure` varchar(10) | **출국일**. `student_modify.php:635` datepicker, `:2282` 필수값 검증 | **시각 없음**. 우리가 필요한 핵심이 빠져 있다 |
| `student_info.s_flight` varchar(200) | 픽업일정 자유텍스트(`KE 645 01:35am(13day)`) | 입국용. 출국편은 정형 필드 없음 |
| `student_info.s_sdate` / `s_edate` varchar(10) | 시작일 / 종료일 | **무료 체류 규칙의 입력값**. varchar 이므로 요일 계산 전 파싱 필요 |
| `student_info.s_age` int | 등록 시점 나이(정수) | **생년월일이 아니다.** 장기 학생은 재원 중 나이가 바뀐다 → 만나이 판정 불가 |
| `student_info.s_jumin` varchar(20) | `881218-`, `920413`, `//`, `-`, `2` … | **형식 붕괴**. 파싱 가능한 행이 일부뿐 |
| `student_info.s_info` text | `[Date of birth]=1988/12/18`, `birthday: 1992/9/21`, `Date of birth : 20 NOV 1972` | **생년월일이 자유텍스트로만** 존재. 포맷 3종 이상 |
| `student_info.s_nation` | `jap`, `kor`, `chi`, `twa`, `rus`, `sa` … 소문자 코드 | 엑셀은 `JAP/KOR/CHI/TWA/RUS/SA` 대문자 → 매핑표 필요 |
| Sending Fee | `student_modify.php:1687` **`prepaid-sendingfee` + `prepaid-sendingfee-date`** (선불 항목) | **금액을 사람이 직접 타이핑**. 요율표 없음. 요청 여부·시각·인원·픽업지 없음 |
| `room_reserve` / `reserve_info` | 침대 × 날짜 1행 | **연장 가능 여부 판정의 정본** — 이미 있다 |
| 졸업식 | **없음** | 테이블·필드 전무 |

> **핵심 결론 3가지**
> ⑴ **출발 시각**, ⑵ **생년월일**, ⑶ **졸업식** — 이 3개는 레거시에 **존재하지 않는다**. 신규 필드로 만들어야 한다.
> 나머지(방·연장가능·방이동·요금)는 **이미 있는 데이터로 파생 가능**하다.

### 2.2 입력 항목 (한 학생 = 한 행 / 상세는 모달)

| 필드 | 형식 | 필수 | 비고 |
|---|---|---|---|
| 출발일 `depart_date` | date | ● | 기본값 = **무료 퇴실 마감일**(§4.1) 프리필 |
| 출발시각 `depart_time` | time (24h) | ● | **24시간제 강제**. `13:00pm`·`12:00nn` 같은 표기 혼선 원천 차단. 리포트 출력 시에만 `1:00pm` 로 포맷 |
| 항공편 `flight_no` | text(30) | ○ | `PR433`, `later` 허용 |
| 픽업 출발지 `pickup_from` | 선택 | ○ | 기본=현재 방의 숙소. `S hotel`/`Canberry`/`Amethyst`/`outsider` |

| 센딩 시각 `sending_time` | time | 조건부 | 기본값 = 출발시각 − 리드타임(§4.3) |
| 센딩 인원 `sending_pax` | int | 조건부 | 실측 `sending 08:30am (2pax)` 케이스 |
| 센딩 목적지 `sending_dest` | 선택 | 조건부 | 공항(MCIA) 기본 |
| **졸업식** `ceremony_attend` | 참석/불참/해당없음 | ● | §5 |
| 졸업식 회차 `ceremony_session` | 선택 | 조건부 | 금 오전/금 오후 등. 마스터는 `app.ceremony_sessions` |
| 비고 `memo` | text | ○ | 기존 자유텍스트 이관 대상 |
| 확정 `confirmed_at` | ts | ― | 확정 후 수정은 사유 필수 + 감사로그 |

### 2.3 입력하는 즉시 화면에 뜨는 것 (규칙엔진 실시간 호출)

1. **🟢무료 / 🔴추가요금** — 무료 퇴실 마감 대비 초과 박수 + 금액(§4.1, §4.2)
2. **연장 가능 여부** — 현재 침대를 그대로 쓸 수 있나(§4.3). 불가면 **대안 침대/외부숙소 제안**
3. **센딩비** — 요청 켜는 순간 금액 표시 + 인보이스 미리보기 줄(§4.4)
4. **미성년 배지** — 만나이 계산 결과. 🔴 = 대상, ⬜ = 생년월일 미확보(§4.5)
5. **가족 일괄** — 같은 방·같은 `(family)` 그룹이면 **한 번에 같은 값 적용**(실측 최다 반복 작업)

### 2.4 하지 말아야 할 것 (실측 기반 UX 결정)

- **출발일에 캘린더 자유입력만 두면 안 된다.** 실제 값은 졸업일(금) 또는 그 다음날(토) 에 90% 몰린다.
  → **[졸업일] [+1일] [+2일] 3버튼**을 기본으로 두고 캘린더는 보조.
- **시각을 텍스트로 받지 않는다.** 위 §1.1 표기 붕괴가 전부 여기서 나왔다.
- **가족 구성원을 개별로 강제 입력시키지 않는다.** 엑셀에서 빈칸으로 남은 이유가 그것이다.

## 4. 규칙엔진 (이 기획의 핵심)

### 4.1 무료 체류 마감일 — 「금 시작→금 / 토 시작→금 / 일 시작→토, 13:00」

**입력**: 입실요일(= `s_sdate` 의 요일, 실제 체크인이 있으면 그것 우선) · 졸업주차
**출력**: `free_until_date` + `free_until_time = 13:00`

| 입실 요일 | 무료 퇴실 마감 | 근거 |
|---|---|---|
| **금** | 졸업주 **금** 13:00 | 요청 명시 |
| **토** | 졸업주 **금** 13:00 | 요청 명시 |
| **일** | 졸업주 **토** 13:00 | 요청 명시 |
| 월~목 | **미확정 → D-1** | 요청에 없음 |

> **일반화 가설(권고안, 확인 필요)**: `무료 퇴실일 = max(입실요일 − 1일, 금요일)`
> — 토→금 ✓ / 일→토 ✓ / 금→(목이지만 하한 금)→금 ✓ 로 **주어진 3건을 모두 만족**한다.
> 이 가설을 채택하면 월~목 입실자는 전부 **금 13:00** 이 된다. 실제 운영과 맞는지 **§9 D-1 에서 확인 필요**.
> 확인 전까지는 월~목 입실자에게 **판정을 내리지 않고 "규칙 미정의 · 수기 확인" 회색 배지**를 띄운다. (틀린 금액을 자동으로 물리는 것보다 안전하다)

**13:00 경계 처리**
```
depart_ts = depart_date + depart_time
free_ts   = free_until_date + 13:00

depart_ts <= free_ts                          → 🟢 무료 (extra_nights = 0)
depart_date == free_until_date, time > 13:00  → 🟡 레이트 체크아웃 1건        (D-3)
depart_date >  free_until_date                → 🔴 extra_nights =
        (depart_date − free_until_date) + (depart_time > 13:00 ? 1 : 0)
```
즉 **13:00 을 넘기면 그 날도 1박으로 센다.** 실측 예: WANG ZHENG(327) `23:00pm (7d)` — 졸업 당일 23시 출발이라
"당일 출발"인데 13시를 넘겼다 → 현재 엑셀은 요금 표시가 없다. **이 케이스가 지금 새고 있는 돈이다.**

### 4.2 방 추가요금 (extra_night)

`amount = extra_nights × unit_price(방타입, 숙소, 시즌)` — 단가는 `app.fee_rules` 에서 조회.
- 단가 소스가 **아직 없다**(레거시는 `fee_dorm1`/`fee_etc1` 에 사람이 총액을 타이핑). → **§9 D-2**
- 계산 결과는 **자동 청구하지 않는다.** 창구가 [인보이스 반영] 을 눌러야 `app.departure_charges` + 인보이스 라인이 생긴다.
  (레거시 인보이스 발행은 append-only 이고 중복 방어가 전무하다 — 자동 발행은 금지)

### 4.3 「해당 방으로 연장 가능한가」 판정

```
연장 필요구간 = (free_until_date + 1일) ~ depart_date
현재 침대 r_idx 에 대해 그 구간 전 일자를 검사:

  legacy.room_reserve   해당 일자에 다른 s_idx 존재?     → 점유
  app.room_assignments  미래 배정(확정/미확정) 존재?      → 점유(미확정은 ⚠)
  app.room_blocks       차단(청소/수리) 존재?             → 차단

전부 비어 있음                  → 🟢 연장 가능 (같은 방 유지)
일부 점유/차단                  → 🔴 연장 불가 → 대안 제시
```
**대안 제시 순서** (방이동 기획서의 충돌검사 로직 재사용)
1. 같은 방의 다른 침대 → 2. 같은 숙소·같은 성별그룹의 빈 침대 → 3. 외부숙소(`S hotel`/`Canberry`/`Amethyst`)
성별(`room_category.g_type`)·가족실 규칙은 방이동 기획서 §충돌검사와 **동일 함수**를 호출한다(규칙 이원화 금지).
연장 불가로 방을 옮기면 그건 **방 이동 1건**이다 → `app.room_moves` 에 자동 생성 → **리포트 ③ room change 칸이 자동으로 채워진다.**

### 4.4 센딩비 (sending)

- `sending_requested = true` 인 순간 `app.fee_rules(kind='sending')` 조회 → 금액 표시.
- 요율 축: **목적지(공항/시내) × 차량/인원 구간(1~3pax, 4~7pax…) × 시간대(심야 할증)**.
  현재 요율표가 **문서로 존재하지 않는다** → **§9 D-4**.
- 이미 선불로 낸 학생은 레거시 `prepaid-sendingfee`(+ `-date`) 에 값이 있다 → **선불 있으면 `prepaid` 배지 + 청구 0**.
- 센딩 시각 기본값 = 출발시각 − 리드타임. 리드타임 기본 3시간(국제선) 이되 `app.fee_rules` 와 별도 `app.ops_params` 로 조정 가능.
- 리포트에서 센딩 행은 **기존 초록(`FF92D050`) 유지** — 현업이 이미 그 색으로 읽고 있다.

### 4.5 미성년 하이라이트 (빨간 형광)

```
기준일 = depart_date (출발 시점 만나이. 등록 시점 아님)
만나이 = floor((depart_date − birth_date) / 1년, 생일 경과 반영)

nationality_iso == 'KOR' 이고 만나이 < 18   → 🔴 미성년
nationality_iso != 'KOR' 이고 만나이 < 17   → 🔴 미성년
birth_date 없음                              → ⬜ 회색 빗금 "생년월일 미확보" (경고, 미성년 판정 보류)
```

**색 규약(변경)**

| 표시 | 색 | 적용 범위 | 변경점 |
|---|---|---|---|
| 미성년 | **빨강 형광 `#FF4D4D` (엑셀 `FFFF4D4D`) · 글자 흰색 굵게** | **age 칸 + Name 칸** | 신규. 기존 노랑 `FFFF00` 을 **대체** |
| 센딩 요청 | 초록 `FF92D050` | 행 전체 | 유지 |
| 추가요금 발생 | 주황 `FFFFC000` | DEP. TIME 칸 | 신규 |
| 생년월일 미확보 | 회색 `FFD9D9D9` | age 칸 | 신규 |

> 노랑을 없앨지 남길지는 **§9 D-5**. 기본 제안은 **폐지**(빨강 하나로 통일해야 "빨간 칸 = 인솔/보호자 확인 대상"이 명확)

**생년월일 확보 전략** (없으면 이 기능 전체가 동작하지 않는다 — 최우선 선행과제)
1. `s_jumin` 이 `YYMMDD` 6자리 숫자로 파싱되는 행 → 자동 채움(`birth_src='jumin'`, **세기 판정 필요**: 30 이상이면 19xx)
2. `s_info` 자유텍스트에서 `Date of birth`/`birthday`/`생년월일` 패턴 추출 → **검토 큐에 넣고 사람이 승인**(자동 확정 금지)
3. 나머지 → 창구/입학팀이 여권 기준 수기 입력. **미확보 학생 리스트를 별도 화면으로 제공**
4. 폴백: `s_age` + `s_date`(등록일) 로 **추정 나이만** 계산해 "추정" 배지. **추정값으로는 빨강을 칠하지 않는다.**

### 4.6 규칙 버전 관리

모든 판정은 `rule_ver` 를 함께 반환한다. 청구 스냅샷에도 남긴다.
"지난주엔 왜 다르게 나왔나"에 답할 수 없으면 현업이 시스템을 안 믿는다.

## 5. 졸업식(Graduation Ceremony)

- 마스터 `app.ceremony_sessions` — 주차별 회차(일시·장소·정원).
- 학생별 `departures.ceremony_attend` = 참석 / 불참 / 해당없음(중도퇴소·외부숙소 등).

  실측에 `8:00am(7d)` 처럼 **졸업식 시간대 이전 출발**이 다수 있다 → 이 경고가 실제로 매주 뜬다.

- 동반 하객(가족) 인원은 `ceremony_guest` 로 별도 집계(정원 관리용). 요금은 기본 0.

## 6. 산출물 — Weekly Report 생성

### 6.1 생성 규칙

- **주차 정의**: 리포트 표지는 **월~금**(`03/Aug - 07/Aug/2026`), 집계표(①)는 **토요일 기준**. 실측 그대로 유지한다.
- ① Students' status = 향후 4개 토요일 각각에 대해
  `New` = 해당 주 신규 입실자 수 / `Extension` = 연장 등록 수 / `Graduation` = 해당 주 졸업(과정 종료)자 수
- ② 졸업자 명단 = `s_edate` 가 해당 주 금요일인 학생 전체. **정렬은 실측대로 `DEP. TIME` 오름차순**(창구/차량 배차 순서와 같다).
- ③ room change = `app.room_moves` 중 해당 주 확정/완료분 자동 추출.
- ④ extend = 연장 등록분. `After` = 연장 후 방(= 방이동 결과), `COURSE` = 연장 과정.
- **발행 시 스냅샷**(`app.weekly_reports.payload`) 을 굳힌다. 사후에 데이터가 바뀌어도 **배포된 리포트는 불변**.

### 6.2 엑셀 내보내기 열 매핑 (기존 레이아웃 보존 + 신규 2열)

| 엑셀 열 | 기존 | 신전산 소스 |
|---|---|---|
| B | NO. | 행 번호(자동 재채번) |
| C | Date | `grad_date` |
| D | Nat | `nationality_iso` → 기존 3자 표기(`TWA/CHI/JAP/KOR/RUS/SA`)로 역매핑 |
| E | Name | `e_name` + 가족이면 `(family)` |
| F | Room No. | 현재 방 또는 숙소명 |
| G | DEP. TIME | `depart_time` + `(Nd)` — **기존 표기 그대로 재현**(현업 가독성 유지) |
| H | sending | `sending_time` + `(Npax)` + 픽업지 |
| I | age | 출발일 기준 만나이. 미성년이면 **빨강 형광** |
| **J(신규)** | ― | **Ceremony** (참석/불참) |
| **J+1(신규)** | ― | **Extra fee** (추가요금 박수·금액, 0이면 공백) |
| K~M | room change | `app.room_moves` |

> 신규 2열은 **오른쪽 끝이 아니라 age 다음**에 넣는다. 인쇄 시 한 페이지 폭 안에 들어와야 창구에서 쓴다.
