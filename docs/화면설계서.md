## 0. 설계 원칙

| # | 원칙 | 근거 |
|---|---|---|
| P1 | **캠퍼스 코드 단일화** — 화면 어디서나 `campus_id`(1=ENCANTO / 4=CLASSIC / 5=CAPITAL) 하나만 사용. 레거시의 sparta·classic·capital / 1·4·5 / S·C·E 3중 표기를 UI에서 제거. | 캠퍼스 코드 불일치(11장) |
| P2 | **국문/영문 이원화 폐지** — 화면 파일을 언어별로 나누지 않고 i18n 토글 1개. | 개선포인트 1 |
| P3 | **캠퍼스별 화면 분기 폐지** — STATUS rey/sparta/classic/capital 4파일 → `campus` 파라미터 단일 화면. | 개선포인트 2 |
| P4 | **의미의 색상화** — 성별·결제상태·학생상태를 텍스트가 아닌 색 칩으로 즉시 판독. | 정보밀도 화면 |
| P5 | **대용량 안전** — 방변경로그 552K·학생 90K는 서버 페이징 + 가상 스크롤 전제. 전체 select 금지. | 데이터 규모 |
| P6 | **원본 불가침** — 조회는 Supabase 이관본/호환뷰 기준. 레거시 MySQL 원본은 읽기전용. | 이관 원칙 |

## 1. 정보구조 (IA / Sitemap)

상단 4대분류가 좌측 서브메뉴 세트를 전환한다.

```
[Record]  [Student's]  [Dormitory]  [Cash Cards]      전역: 캠퍼스필터 · 검색 · 계정
   │           │             │            │
   │           │             │            └─ 현금/입출금
   │           │             └─ 기숙사 배치·이동·요금·방문·일정
   │           └─ 학생·수강·수금·통계·게시판
   └─ 홈/대시보드 (독립 하위메뉴 없음 → 신규는 종합 대시보드로 승격)
```

레거시에서 Record는 독립 메뉴가 없었음 → 신규는 **첫 진입 종합 대시보드**로 사용.
KPI · 오늘의 입/퇴실 · 미납 현황 · 캠퍼스별 재실률 · 최근 방변경 로그.

## 3. 핵심 화면 상세 와이어프레임

### 3-1. 대시보드 `/`
```
┌ KPI 행 ─────────────────────────────────────────────┐
│ [학생 90,527] [재실 1,127실·92%] [오늘 입실 34/퇴실 27] [미납 1,208건] │
├ 캠퍼스별 재실률(막대) ── 국적 분포(도넛) ── 최근 방변경 로그(리스트) ┤
│ 오늘의 입/퇴실 타임라인 ─────────────────────────────  │
└──────────────────────────────────────────────────────┘
```

### 3-2. STUDENT LIST `/students`
- **필터바**: DEPARTURE(기간) · AGENCY · NAT · 상태 · 검색(이름)
- **테이블 컬럼**: ☑ · AGENCY · NAT · 이름(EN) · 이름(KR) · 생년월일 · AGE · SEX(색칩) · APPLY · DEPA · PIC · 등록일 · [상세]
- **일괄처리**: 선택 → 상태변경/내보내기

### 3-3. DEPOSIT `/deposits`
- **필터바**: GROUP(YYMM) · NAT · STATUS(N/Y/X/R) · CAMPUS(전역필터로 대체) · 기간(BEGIN/END) · NAME
- **테이블**: NO · NAT · NAME · BEGIN · END · STATUS(색칩) · DEPOSIT(금액, 우측정렬 tabular)

### 3-4. 기숙사 현황 배치도 `/dorm/status`
- **범례**: ■남(파랑) ■여(빨강) ■공용(노랑) ■빈방(회색)
- **그리드**: 구역(zone)별 그룹 → 방 셀(방번호·인실 CAPA·재실자수). 셀 색=성별. 호버 시 재실자·기간 툴팁.
- **배치문자열 정규화**(개선5): `E203:4bed:ENCANTO2=4weeks` → room_id+capacity+campus+weeks 구조로 렌더.

### 3-5. 방변경 백업로그 `/dorm/change-log` (audit)
- **필터**: 매니저 · 학생ID · 이름 · 기간
- **테이블**: AGENCY · ID# · STUDENT · CHANGE TIME · STUDY PERIOD · PRE-DORM · CHANGE-DORM · MANAGER
- **성능**: 552K → 서버페이징·(student_id, changed_at) 인덱스·월 파티셔닝 전제(P5).

### 3-6. Admission Date `/dorm/admission`
- **그리드**: 캠퍼스 × 성별(남/여) × 인실(1~4) → 입학가능일 셀
- **부가**: 공지 영역(취소자리 대기·연락처).

## 4. 화면 상태(state) 규칙
- **로딩**: 스켈레톤 행. **빈결과**: "조건에 맞는 데이터 없음 + 필터 초기화" 안내(사과문구 금지).
- **에러**: 무엇이·왜·다음행동 명시.
- **대용량 경고**: 필터 없이 전체 조회 시 "N만 건 — 필터를 좁히세요" 가드.

### 4-1. ★ 저장·인보이스 발행 중복실행 방지 (Idempotency) — 필수
> 레거시 최대 병폐(예약 완전중복 88쌍·유령행·room_reserve 280만 비대화)를 **UI/서버 양쪽에서 원천 차단**.

| 계층 | 규칙 |
|---|---|
| 클라이언트(더블서밋 가드) | 저장/발행 버튼 클릭 즉시 **비활성화 + "처리 중…" 스피너**. 처리 중 재클릭 → `이미 실행 중입니다` 토스트, 재전송 차단. |
| 서버(멱등키) | 요청에 `idempotency_key`(폼 진입 시 발급 UUID) 첨부. 동일 키 재수신 시 **신규 INSERT 없이 최초 결과 반환**. |
| DB(유니크 제약) | 인보이스 `UNIQUE(invoice_no)` 또는 `UNIQUE(student_id, period, type)`; 예약은 기적용 `uq_res_no_dup`. 경합 시 409 / "이미 발행됨". |
| 장기작업 락 | 엑셀/일괄발행은 `processing` 상태 플래그로 중복 트리거 차단, 완료/실패 시 해제. |

- 적용 화면: **Cash > Manage Cash(저장)**, **변경환불홀딩·CHG-REF-HOLD(INVOICE 발행)**, 그룹결제 발행, 예약/입퇴실 저장 등 **레코드 생성 액션 전반**.
- 프로토타입에서 동작 확인 가능: [prototype.html](./prototype.html) Cash Cards → 인보이스 발행 2회 클릭.
