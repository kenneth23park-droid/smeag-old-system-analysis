## 0. 설계 원칙 (전 요구 공통 · §28)

| 원칙 | 신전산 적용 방식 |
|---|---|
| 레거시 원본 불가침 | 모든 쓰기는 `app.*` 오버레이 + 읽기 시 덮어쓰기. `legacy.*`·`cms.*` 는 UPDATE 금지 |
| 하드코딩 금지 | 캠퍼스·코스·객실카테고리·국적은 마스터 테이블 참조. 화면 상수 배열 금지 |
| 불변 ID | 표시명 변경이 통계·인보이스를 깨지 않도록 `*_id` 참조, 이름은 별도 컬럼 |
| 금액 정밀도 | `numeric`(Decimal). 부동소수점 금지 |
| 가격 스냅샷 | 인보이스 발행 시 적용 단가를 `price_snapshot` 으로 고정 |
| soft delete | 물리삭제 금지, `active=false` / `released_at` |
| 감사 | 모든 쓰기 RPC 가 `app.write_audit` + `app.log_change` 기록 |
| 멱등 | 쓰기 요청은 멱등키 필수 + DB 유니크 제약 (더블서밋 3중 방어) |
| 삭제 보호 | 삭제 계열 작업은 로그인 비밀번호 재확인 토큰(5분·목적한정) |
| 단일 산출원 | 재학생 수·점유는 하나의 집계 서비스만 사용. 화면별 자체 쿼리 금지 |

## 1. P0 — 반드시 우선

### REQ-101 수강등록 검색 완결 🟡
- 검색기준에 **"특정 날짜의 재학생"**(시작일 ≤ D ≤ 종료일) 추가.
- **담당자(매니저) 필터** 추가.
- 멀티 코스 선택은 개수 제한 없음 ✅(구현됨).
- **AC**: 같은 조건으로 레거시 `student_list.php` 와 결과 건수가 일치한다. 코스 5개 동시 선택 검색이 1회 조회로 끝난다.

### REQ-102 미처리 학생 경고 목록 ⬜
- 별도 하단 패널/탭. 상단 화면을 가리지 않는다(100건 이상 전제).
- 대상: 객실 미배정 · 인보이스 미발행 · 객실 삭제/누락 · N일 이상 미처리 · 입국예정인데 항공/픽업 없음.
- 표시: 이름·국적·등록일·경과일수·담당자·누락항목·캠퍼스·유학원·바로처리 버튼.
- 필터: 누락유형·담당자·국적·캠퍼스·등록일 범위.
- **AC**: 임의 학생의 객실 배정을 지우면 그 학생이 목록에 나타나고, 배정하면 사라진다.

### REQ-103 기숙사 현황 정합 🟡
- 조회 기간 내 객실의 **모든** 학생 표시 ✅.
- 선택 월이 화면 **왼쪽 시작점**(현재는 13개월 창의 중앙).
- 침대 식별자(`r_idx`)를 프론트에 노출 → 이동 대상 침대 지정 가능.
- **AC**: 7월 선택 시 초기 스크롤 위치가 7/1. 객실 이동한 학생이 이동 전·후 방에 모두 보인다.

### REQ-104 같은 날짜 입·퇴실·이동 동시 처리 🟡⚠
- 한 셀에 두 이벤트 동시 표시 ✅(대각선 분할).
- **이벤트 원장 신설**: `app.room_events`(check_in/check_out/move_in/move_out + 시각·사유·담당자).
- **AC**: 같은 방·같은 날 퇴실 1 + 입실 1 을 저장하면 두 건 모두 남고, 다음 날로 밀리지 않는다.

### REQ-105 일별 재학생 수 단일 산출원 ⬜⚠
- 재학생 수는 **유효 배정 레코드**로 계산(셀 개수 금지). 관리용 가상학생 제외. 이동 중복집계 금지.
- **식수 예상 인원은 별도 계산·별도 리포트**(퇴실자+신입 동시 식사 가능).
- **AC**: 임의 5개 날짜에서 배치도·일별입퇴실·STDNT STATUS 세 화면의 재학생 수가 동일하다.

### REQ-106 MC Report 2 재설계 ⬜
- 축 = **코스(행) × 날짜(열)**. 기본 15일, 시작일 달력 선택. 캠퍼스별 조회. 날짜별 전체 합계.
- 코스명 하드코딩 금지 → 코스 마스터의 활성 코스가 자동으로 행에 추가.
- 헤더(코스명·날짜) 고정, 가로·세로 스크롤, 엑셀.
- **AC**: 새 코스를 만들면 저장 즉시 MC Report 2 에 행이 생긴다. 비활성 코스는 설정에 따라 숨는다.

### REQ-107 캠퍼스 마스터 + 코드 단일화 ⬜⚠
- 관리자 화면에서 캠퍼스 생성·이름변경·영문명·코드·활성·정렬·수용정원·홈페이지 노출.
- 기존 코드 4중(sparta/1/S/SP + 이름) 및 화면별 상충 매핑을 `campus_id` 로 흡수.
- 신규 캠퍼스는 수강등록·코스·기숙사·객실·MC Report·STDNT STATUS·Admission Date·통계·권한설정에 자동 반영.
- **AC**: 캠퍼스를 하나 새로 만들고 코드 변경 없이 위 9개 화면에서 선택지로 보인다. 이름을 바꿔도 기존 학생·인보이스·통계가 깨지지 않는다.

### REQ-108 기숙사 카테고리 마스터 ⬜
- 카테고리 생성·정렬(`sort_order`)·성별/타입·활성. 알파벳 정렬 금지.
- **AC**: 카테고리 순서를 바꾸면 배치도·DORM LIST·DORM SEARCH 순서가 함께 바뀐다.

### REQ-109 기숙사 변경 감사 로그 🟡
- 검색 실동작: 학생명·학생ID·객실번호·작업자·기간·작업유형·캠퍼스. 서버 페이징(300건 상한 폐지).
- 신전산 쓰기(`app.write_audit`/`change_log`)와 레거시 `room_change_log` 를 **한 화면**에서 조회.
- 일반 사용자 삭제·수정 불가(관리자 전용 읽기).
- **AC**: 2019년 이력이 조회된다. 방막기·이동·배정 변경이 작업자와 함께 남는다.

### REQ-110 인보이스 정확성·중복방지 ✅🟡
- 중복 발행 방지 ✅(UI잠금+멱등키+UNIQUE+중복안내).
- **가격 스냅샷 추가**: 발행시점 코스 주단가·객실 주단가·커미션율·환율을 `price_snapshot` 에 고정.
- 버전 관리·최종본 표시·이전 버전 조회.
- **AC**: 인보이스 발행 후 코스 가격을 바꿔도 기존 인보이스 금액·상세가 변하지 않는다. 발행 버튼 연타 시 1건만 생성된다.

### REQ-111 객실·코스 가격 일괄 업데이트 ⬜
- 국가/시장 × 인실(또는 코스 × 주차) 매트릭스 편집. 캠퍼스·타입 필터, 적용 시작일.
- 미리보기(대상 건수·변경 전후) → 트랜잭션 일괄 적용 → 실패 목록 → 변경 로그 → 엑셀.
- **AC**: 일부 실패 시 전체 롤백된다. 적용 후 기존 인보이스 금액 불변(REQ-110과 연동).

### REQ-112 이관 후 객실·학생·코스 검증 리포트 🟡
- 행수 대조 ✅(51~54테이블 100% 일치 실증).
- **객실 차이 리포트 8종 신설**: 레거시에만 있는 객실 / 신전산에만 있는 객실 / 비활성 불일치 / 카테고리 불일치 / 성별 불일치 / 최대인원 불일치 / 중복 객실 / 정렬순서 불일치.
- **AC**: 리포트가 자동 생성되고 차이 0건이거나, 차이가 사유와 함께 목록화된다.
